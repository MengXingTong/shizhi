# 拾知 · Shizhi

**把感兴趣的视频，变成可以随时收听的知识摘要。**

简体中文 · [English](README.en.md)

拾知是一款独立运行在 Android 手机上的个人知识收听工具。它根据你的兴趣寻找 B 站视频，读取可用字幕，调用你配置的 AI 服务筛选与提炼内容，再通过手机的文字转语音（TTS）朗读。无需自建电脑后端，但获取视频信息和生成摘要需要联网。

> **当前为 Android 验证版 `0.1.3-alpha1`，不是正式发行版。** 真实手机、B 站账号与模型服务的端到端流程仍待验证。已有自动化测试不等于真机可用性保证。

## 能做什么

- **按兴趣发现内容**：填写兴趣与排除项，筛选推荐视频，也可以指定一个 BVID 或视频链接单独提炼。
- **持续维护待听队列**：待播满时停止生产，消费后按需补充；无需每听几条就重新开始。
- **听摘要、核对来源**：摘要附带字幕引用与时间点，可打开原视频查看；重听已保存的摘要不重复调用模型。
- **保留值得回听的内容**：支持历史、收藏与按句恢复进度。普通历史保留 7 天，收藏不受此期限影响。
- **自己选择 AI 服务**：配置 HTTPS 地址、API Key 与模型名，使用兼容 Chat Completions 的接口。
- **本机管理数据**：设置与历史保存在手机中，无自建服务端、无云同步，不下载原视频。

## 开始使用

### 1. 准备与安装

需要 Android 8.0（API 26）及以上、可用的 Android WebView、中文 TTS 引擎、你有权使用的 B 站账号，以及兼容的 AI 服务。

当前构建输出为 `dist/shizhi-0.1.3-alpha1-debug.apk`。`dist/` 不纳入版本控制；如果拿到的是源码，请先按下方步骤构建，而不是把该路径当成下载链接。只安装你信任来源的 APK。

升级时使用相同包名与签名覆盖安装，**不要先卸载**，以保留设置、历史和收藏。自己重新构建时也要保留本机调试 keystore；不同签名不能直接覆盖安装。调试签名不适用于正式发行。

### 2. 配置接口与语音

1. 打开底部「设置」，保存 **HTTPS Base URL、API Key、准确的模型名**。
   - OpenAI 官方接口示例：`https://api.openai.com/v1`。其它服务按其要求填写，不自动补 `/v1`。
   - API Key 留空保存表示沿用已保存的 Key，明确勾选清除才会删除。
   - 模型不支持 `max_tokens` 时，可切换为 `max_completion_tokens`。
2. 在「刷视频 → 功能设置」填写兴趣和排除项，通过 B 站官方网页完成登录。未自动返回时可点「重新检查」。
3. 点击「测试语音」。没有中文声音时，先到系统语音设置安装或启用相应引擎。

**「测试连接」会在确认后发送真实模型请求，可能产生费用。** 不要把 API Key 或 Cookie 发到问题报告或聊天中。

### 3. 先试一条，再连续收听

1. 在「先验证一个视频」输入你能访问且已知有字幕的 BVID 或完整 B 站视频地址。
2. 点「检查字幕」。这一步不调用模型；无字幕时不会自动下载视频或调用语音识别。
3. 确认字幕可用后点「提炼这条」，确认数据去向和费用，再核对摘要、引用与播报效果。
4. 单条流程正常后，回到「待听」点「刷视频」，开始持续筛选和补充队列。

## 收听与费用如何控制

| 操作或状态 | 行为 |
| --- | --- |
| 待播达到上限 | 默认 3 条，可设 1–10 条；不含当前播放项。队列满时停止生产，不继续调用模型。 |
| 暂停 / 继续刷取 | 保留待播队列，与播放器的播放 / 暂停分开。 |
| 重新刷视频 | 确认后将旧待播移入历史，用最新偏好开始；不打断当前播报，不删除收藏。保存偏好本身不会清队列。 |
| 连续没有匹配内容 | 降低查找频率后继续，不靠降低兴趣阈值凑满队列，也没有固定批次数上限。 |
| 请求失败 | 临时的 B 站只读请求可自动重试；模型请求不会盲目重发。需要处理的错误保留队列并显示恢复入口。 |
| 应用被关闭或系统终止 | 保存队列与进度，重启后提供继续入口，不自动重新发出付费请求。 |

持续发现新候选可能产生筛选和摘要费用。要停止新增请求，请**暂停刷取**，而不只是暂停音频；服务商已开始处理的请求即使取消仍可能收费。系统 TTS 是否联网取决于所用引擎。

## 当前限制

- B 站推荐和字幕依赖非公开接口，可能因接口变化、登录状态、风控或账号权限不可用；不绕过验证码、付费或访问权限。
- 当前读取第一分 P。字幕超过输入长度设置（默认 12,000 字符）时只处理开头，并标注节选。
- 来源绑定、字幕引用和时间点用于核对取数与摘要，不是对平台字幕归属或视频观点的独立事实核查。
- Android 后台限制、省电策略、通知权限与设备 TTS 差异会影响持续运行；锁屏、后台服务和升级恢复仍需真机验证。
- 这是 Java 原生能力与本地 WebView 界面的验证实现，**不是已完成的 Kotlin / Compose / Room 版本**。英文文档不代表应用已提供英文界面。

## 隐私与数据流

- API Key 与 B 站 Cookie 使用 Android Keystore 保护的 AES-GCM 加密保存；系统应用备份已关闭。
- 兴趣、候选视频元信息和字幕会发送给你配置的 AI 服务，首次生产及接口地址变更后需要确认数据去向。AI 服务的处理与留存受其政策约束。
- Cookie 仅用于 B 站请求，不发送给字幕 CDN 或 AI 服务。官方登录页与本地业务界面隔离。
- 本地界面使用打包资源，不加载外部业务脚本；历史保存在本地 SQLite 中，不包含原始凭据。
- 网络请求使用 HTTPS。模型 POST 不自动重试或自动代理回退，避免重复计费；不要据此假定应用一定绕过系统 VPN。

## 从源码构建

**环境：Windows、PowerShell 7、JDK 17。** Android API 35 与 Build Tools 35.0.0 由脚本下载并校验。

在项目根目录运行：

```powershell
./scripts/bootstrap.ps1
./scripts/build.ps1 -JavaHome 'C:\Program Files\Java\jdk-17'
```

无需 Gradle、Android Studio 或 npm 即可生成 APK。输出位于 `dist/`，调试签名在忽略的 `tools/shizhi-debug.jks`。不要提交签名文件、凭据或本机配置。

### 测试

```powershell
# JVM 核心逻辑测试；org.json 依赖只用于测试，不打入 APK。
./scripts/bootstrap-tests.ps1
./scripts/test-core.ps1 -JavaHome 'C:\Program Files\Java\jdk-17'

# 使用 Python 标准库验证 SQLite SQL，不是 Android instrumentation。
python ./tests/test_sqlite.py

# Node.js / Playwright 界面测试，需要本机 Chrome。
npm install --ignore-scripts
npm run test:syntax
npm run test:ui
```

可用 `CHROME_PATH` 指定 Chrome，`SHIZHI_NODE_MODULES` 指定已有 Playwright 所在的 `node_modules`。测试使用替身，不验证真实 B 站登录或付费模型调用。历史验证结果与待验事项见[验证记录](design/VALIDATION.md)。
