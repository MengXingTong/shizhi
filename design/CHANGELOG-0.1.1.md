# 0.1.1-alpha1 · 2026-11-03

针对用户真机反馈的一次修复包。版本码 2，包名仍为 com.shizhi.app，沿用调试签名。

## 问题与修改

1. 验证码网页实际成功，但没有自动返回：
   - 增加页面完成/历史变化触发与前台本地 Cookie 检测，覆盖 AJAX 登录不整页跳转的情况。
   - 合并 API/www/passport/root Cookie；只在有 SESSDATA 时发账号确认请求。
   - 纯逻辑门闩避免重复验证，账号变更可再检查；失败显示原因且允许手动重试，不要求重拿验证码。
   - 登录确认使用更短的独立超时，不改变模型调用超时；成功后在主线程提交凭据，防止关闭/退出与迟到结果竞争。
2. 保存前用户名不更新：
   - 回归测试在修复前复现了问题：apply() 为保留草稿而直接返回，账号区域也未刷新。
   - 改为独立实时账号卡片；功能表单仅保存可编辑偏好，不包含登录状态。
   - 测试确认用户名/退出按钮立即更新，同时保留未保存兴趣、待播数和选区焦点。
3. 字幕地址统一报域名不允许：
   - 旧代码拒绝 HTTP、未检查 v2 字段，且优先轨道即便 URL 为空也会被选中。
   - 新策略先规范化 URL，升级可信 HTTP，保留原始签名路径/参数，验证域名边界、端口、userinfo 等。
   - 只允许 hdslb.com、bilibili.com、bilivideo.com 及其子域；只对字幕 GET 有限跟随可信跳转。
   - 空/坏地址不挡住其它可用轨道；单条字幕不可用跳过，认证/限流仍停止。未知 CDN 显示纯域名用于排查，不显示完整签名 URL。
   - 这修正了已知处理缺陷，但未拿到用户报错的原始字幕地址，不能把替身测试说成该链接真机已成功。
4. 一直等待补货且缺少运行状态：
   - 播放器原先写入与生产共用的 message，可把字幕错误覆盖成「等待补货」。现已分离 playbackNotice。
   - 原生推送当前阶段、阶段开始时间、候选计数、去重数、视频与最近跳过原因。
   - UI 状态面板显示运行/满队列/结束/错误的区别；计时器只更新本地文字，不请求模型或轮询后端。

- 15 项浏览器 UI 检查通过（原 9 项加实时账号/草稿保留、阶段/计时、错误不被播放提示覆盖、无结果原因）。
- 实际 SQL 清理检查通过。
- APK 编译、对齐、v2/v3 签名校验通过。
