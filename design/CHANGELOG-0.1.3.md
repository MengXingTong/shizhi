# 0.1.3-alpha1 · 2026-11-03

## 从使用者的完整流程整改，而不是让用户反复开始

这次发现的根本产品错误：把连续 3 批空结果当成“查找结束”。这不是保护正常收听，而是让用户代替程序不断重开任务，与软件目标相反。此规则已从执行逻辑和当前架构文档移除。旧变更记录仅用于版本溯源，不代表当前行为。

### 已落实的体验检查

| 使用过程 | 原来问题 | 当前实现 |
| --- | --- | --- |
| 点一次开始，想一直听 | 几页没结果就结束 | 不按空批次数结束，持续维护待播目标 |
| 推荐难筛、没有字幕 | 不断手动点开始 | 继续换批，连续空结果逐渐降频并倒计时 |
| 断网又恢复 | 手动重开，可能重复付费排名 | 仅临时 B 站 GET 原位置自动重试，已排名候选仍在本批上下文 |
| 真正需要修配置 | 错误和正常等待混杂 | 需要处理，提供相应入口及保留队列的恢复 |
| 正在听 | 诊断占满首屏、耗时检查可能挡住播放控制 | 当前内容在前、诊断可展开，检查进行中仍可暂停/切换音频 |
| 等下一条 | 可能隐式重听旧摘要 | 显式等待新内容，可取消，不修改自动播放偏好 |
| 保存了新偏好 | 不知道当前还按旧设置刷 | 原生比较当前任务与保存设置，提示尚未应用 |
| 重新筛选 | 误清队列、要先停再开 | 先确认，再取消旧任务后串行切换；旧代际不能入队或触发自动播放 |
| App 被系统终止 | 恢复时容易又清队列 | 保存连续任务意图，启动仅提供继续，不自动计费 |

## 执行架构

新增 `RefillLoop`：真正的持续循环控制器，由 Android Engine 与 JVM 确定性测试共同使用；不是只在测试里重写一个看似正确的循环。Driver 负责容量等待、执行一批和降频等待。`single=true` 的指定单条才在一次处理后结束。

新增 `RefillPolicy`：没有停止阈值。第 1–4 次空批无额外等待，第 5 次起 5/10/20/40/60 秒，再保持最多 60 秒的间隔；成功重置。网络只读重试间隔 5/10/20/40/80/120 秒后保持 120 秒。等待采用可通知的条件等待，不持有 CPU 唤醒锁，不轮询模型；暂停/停止立即取消。消费到空队列可唤醒空结果等待，但不绕过网络退避。

`RefillLoop.read` 只包裹 B 站 username/feed/subtitles/video 的只读操作，且仅对明确的临时网络异常、HTTP 408/5xx 自动重试。模型调用不在此重试包装内，认证/风控/证书/格式错误不误判成普通空结果。发生不确定计费的模型失败时，停止自动重发并保留待播，让用户检查；持续格式校验失败也要求检查，不悄悄重复计费。

Engine 拆分任务上下文、读取重试、单批处理和持续调度，保留单生产者、在途槽位、BVID/CID/字幕来源绑定及 7 天/收藏规则。连续刷取的累计用量不因暂停继续清零。重新刷取用工作队列等待旧任务实际退出，再开启新一代；原生确认取消不改变队列。

## 状态与前后台

- 连续任务正常路径：checking → discovering/ranking/subtitles/summarizing/validating/queued → buffered 或 waiting/retrying → 自动回到查找。
- 空批/无字幕/无匹配/去重不进入 completed/error。
- 只有指定单条正常进入 completed；用户暂停进入 paused；必须处理的失败进入 error 并保留继续入口。
- 自动补货开启时，即使处于条件等待，前台服务不再因为 `producing=false` 被当成任务完成而停止。唤醒锁仍只在实际工作或播报需要时使用。
- Android 后台时限、设备省电、进程终止不能由本应用承诺绕过。服务超时明确说明系统原因；重启只恢复意图/队列，不自动发出付费请求。
- 本地倒计时以原生剩余时长为基准，每秒更新 DOM，不轮询原生/网络/模型。

## 已实际执行

- **64 项 JVM 测试**：真实共享的 RefillLoop 连续 30 空批后补满 3 条；满队列等待消费后只补一条；连续 1000 次收听补货/4000 批没有配额；空等待/容量等待暂停；单条模式有限；GET 原位置恢复；20 次读失败仍自动等待；认证/风控/证书不重试；付费任务失败不重发；多行偏好签名不碰撞。原有字幕来源、摘要引用、网络与容量测试仍通过。
- **28 项本地资源浏览器检查**（原生桥替身）：状态、倒计时不轮询、空队列等待、不重播历史、错误保留队列、取消重刷、未应用偏好、不破坏草稿、播放器顺序、单条文案、320/390/736 布局。连续执行两遍验证展开诊断不会因快速状态刷新被收起。
- 桌面 SQLite 实际 SQL：清队列保留历史/收藏/当前、修复保留收藏、进度清理不删除任务恢复标志。
- APK 编译/对齐/v2 v3 验签，版本码 4，与 0.1.2 同证书，可覆盖安装。
- UI 截图均标注为浏览器/测试示例，不冒充手机实测；没有使用真实账号/模型付费请求。

## 仍需手机复验

1. 连续多个推荐页无结果仍显示自动查找/倒计时，之后能自行入队并继续播放；满目标时不再筛选提炼。
2. 短暂断网后自动继续；对真实风控/登录失效能给明确原因和恢复入口，不伪称网络等待。
3. 暂停保留队列，继续补货不清空；重刷先确认，取消保持现状，确认不打断当前音频。
4. 保存偏好时提示未应用，但不覆盖未保存草稿；重新刷后该提示消失。
5. 手机锁屏、系统前台服务时限、音频焦点、真实 TTS 行为与升级数据保留。

没有接入用户手机/ADB，以上测试不是 Android instrumentation 或真实 B 站/模型端到端成功证明。没有在本轮下载视频或发起付费模型调用。
