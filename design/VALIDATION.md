# Android 验证记录 · 2026-11-03

版本：0.1.0-alpha1。结果范围必须分清「编译」「桌面逻辑/界面替身」「真实手机」。

## 已实际执行

1. Android API 35 / Build Tools 35.0.0 / JDK 17：aapt2 → javac → d8 → zipalign → apksigner。
2. APK v2 / v3 签名校验通过；包名 `com.shizhi.app`，版本码 1，最低 SDK 26，目标 SDK 35，调试签名。
3. **25 项 JVM 核心检查通过**：
   - 容量、在途预留、满队列、并发抢同一槽位、取消与会话代际。
   - 10000 次消费/补货模拟仍可工作，不存在请求次数配额。
   - Base URL 自定义路径、去除末端接口路径、拒绝 HTTP/内嵌账号/查询参数。
   - 7 天边界、收藏/活跃播放豁免、按句切分与 Unicode 完整性。
   - 兼容输出长度参数、usage 缺失与存在、调用失败不重试。
   - 摘要证据与时间点校验、无价值输出、候选 ID 白名单与去重。
   - 直接 GET 失败后代理回退、付费 POST 不回退、不跟随重定向、Cookie 主机限制、请求取消。
   - B 站登录/推荐/字幕解析通过内存 HTTPS 连接替身验证，**不是线上账号验证**。
4. **9 项浏览器 UI 检查通过**：
   - 初次无伪造摘要、两级导航、全局接口保存与 Key 不回显。
   - 功能设置仅待播容量、无请求配额；后台状态变化不破坏未保存输入。
   - 单条字幕诊断不发起模型命令；历史/收藏直接播放已有条目。
   - 不可信标题不作为 HTML 执行。
   - 320/390/736 px 无横向溢出；本地资源，无浏览器 API 请求。
   - 所有原生命令是测试替身，**不是 Android 运行结果**。
5. 使用桌面 SQLite 执行源码中的真实建表/清理 SQL：普通过期、收藏豁免、播放中豁免、7 天边界、过期待播、进度垃圾清理、取消收藏和恢复状态检查通过。
6. 使用真实本地界面资源捕获首次使用/功能设置截图，做了视觉检查；截图明确带浏览器预览标识，不代表原生设备截图。

本次没有用户 Key、Cookie、真实模型调用或真实 B 站登录。没有把测试替身描述为真实业务成功。

## 必须留给真机的验收（尚未完成）

- [ ] 安装和首次启动，无闪退；首次为空，不出现假历史。
- [ ] 官方网页登录和验证码可完成；验证成功后切回主界面。
- [ ] 用已知有字幕且有权访问的视频，检查字幕成功。
- [ ] 用用户自己的 URL/Key/模型做手动连接测试；拒绝确认时不请求。
- [ ] 提炼单条成功，能核对知识点引用与时间点。
- [ ] 系统中文 TTS、暂停续播、上一个/下一个正常。
- [ ] 默认最多当前 1 + 待播 3；满队列模型请求不增长，消费后最多补一条。
- [ ] 改小待播上限不删除现有内容，改大后按新容量补货。
- [ ] 停止在途请求后无旧结果继续入队；已接收请求可能仍被服务商计费。
- [ ] 历史/收藏重听没有模型请求，取消过期收藏先确认。
- [ ] 锁屏通知、耳机按钮、音频焦点丢失和耳机断开正常。
- [ ] 进程终止/设备重启后队列、收藏、句级进度可恢复，不自动重新生产。
- [ ] 通知权限拒绝、无中文语音、网络/认证/风控错误均有清晰提示。
- [ ] 长时间后台与系统省电/服务时限的实际行为可接受。

建议先验收登录和字幕，再调用一次模型。不要一开始就用大量视频测试不确定的接口。
